01 / THE CHALLENGE

Overview

OBJECTIVE

Automate an IoT device

Develop an IoT automation system using an ESP32, IFTTT, Adafruit IO, and MQTT. A predefined external event should update a cloud feed and cause the ESP32 to control an LED without a manual dashboard command.

PROBLEM

Move beyond manual control

A basic connected device is often controlled manually through an app or dashboard. Automation adds a trigger and rules so a configured event can start the action automatically.

Project summary: IFTTT detects a configured trigger and runs an action that updates an Adafruit IO feed. The ESP32 subscribes to that feed over MQTT and changes the LED state in response.

02 / AUTOMATION CONCEPTS

From event to action

IoT automation lets connected systems perform an action when a predefined event or condition occurs, instead of waiting for a person to press a control.

01 / IF THIS

Trigger

An event that starts the automation. The supplied project image identifies Google Assistant voice-trigger Applets; the configured trigger phrase is “Okay Google, activate on/off.”

02 / AUTOMATION

IFTTT Applet

IFTTT means “If This Then That.” An Applet connects a trigger service or event to an action.

03 / THEN THAT

Action

The operation IFTTT runs after the trigger. Here, the action sends a value to Adafruit IO.

04 / DEVICE

ESP32 + LED

The ESP32 receives the cloud command through MQTT and applies it to its GPIO output.

Other possible triggers include a Webhooks event, a button, a schedule, or a connected application. Document the configured trigger accurately if it differs from the voice-trigger example.

03 / END-TO-END ARCHITECTURE

System design & data flow

The automation and device-control layers are separate: IFTTT evaluates the trigger, while Adafruit IO and MQTT deliver the command to the hardware.

TriggerExternal event

Configured event occurs

IFTTTApplet action

Runs the then-that step

Adafruit IOFeed + broker

Stores and forwards value

ESP32GPIO 2 / LED

Applies the command

  1. A predefined external trigger occurs.
  2. IFTTT detects the event and runs the configured Applet.
  3. The Applet action sends the selected command to Adafruit IO.
  4. The bulb-control feed stores the new value.
  5. The MQTT broker forwards it to the subscribed ESP32.
  6. The ESP32 reads the command and selects the corresponding output state.
  7. GPIO 2 changes state and the LED responds.
FEED VALUE: ON

GPIO 2 = HIGH

The ESP32 turns the LED on.

FEED VALUE: OFF

GPIO 2 = LOW

The ESP32 turns the LED off.

Example automation sequence

Trigger occurs → IFTTT detects event → Applet runs action → Feed updates → ESP32 receives MQTT → LED responds.

05 / CLOUD FEED

Adafruit IO feed

Adafruit IO provides the IoT cloud layer between the IFTTT automation and the ESP32. The feed stores the command produced by the Applet action. The ESP32 subscribes to the feed through MQTT and checks for new messages.

MQTT feed / topic: Kixorr_28/feeds/bulb-control. The IFTTT action updates the bulb-control feed, and the ESP32 listens to the matching account feed for ON or OFF.

07 / FIRMWARE

ESP32 MQTT implementation

The device connects to Wi-Fi, authenticates with Adafruit IO, subscribes to the feed, and processes new values. IFTTT updates the feed; the ESP32 sketch handles the cloud-to-device command.

Credentials below are placeholders. Enter credentials locally before upload. Keep Wi-Fi passwords, the AIO Key, and IFTTT service tokens private.

ESP32_IFTTT_MQTT.ino

#include <WiFi.h>
#include "Adafruit_MQTT.h"
#include "Adafruit_MQTT_Client.h"

#define WIFI_SSID "YOUR_WIFI_NAME"
#define WIFI_PASSWORD "YOUR_WIFI_PASSWORD"
#define AIO_SERVER "io.adafruit.com"
#define AIO_SERVERPORT 1883
#define AIO_USERNAME "Kixorr_28"
#define AIO_KEY "YOUR_ADAFRUIT_IO_KEY"
#define LED_PIN 2

WiFiClient client;
Adafruit_MQTT_Client mqtt(
  &client, AIO_SERVER, AIO_SERVERPORT, AIO_USERNAME, AIO_KEY);

Adafruit_MQTT_Subscribe bulbControl = Adafruit_MQTT_Subscribe(
  &mqtt, AIO_USERNAME "/feeds/bulb-control");

void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);
  digitalWrite(LED_PIN, LOW);

  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  Serial.print("Connecting to Wi-Fi");
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println();
  Serial.println("Wi-Fi connected");
  Serial.print("IP Address: ");
  Serial.println(WiFi.localIP());
  mqtt.subscribe(&bulbControl);
}

void connectMQTT() {
  int8_t result;
  if (mqtt.connected()) return;

  Serial.print("Connecting to Adafruit IO...");
  while ((result = mqtt.connect()) != 0) {
    Serial.println(mqtt.connectErrorString(result));
    mqtt.disconnect();
    delay(5000);
  }
  Serial.println("Connected to Adafruit IO");
}

void loop() {
  connectMQTT();
  mqtt.processPackets(1000);

  Adafruit_MQTT_Subscribe *subscription;
  while ((subscription = mqtt.readSubscription(1000))) {
    if (subscription == &bulbControl) {
      String command = (char *)bulbControl.lastread;
      command.trim();
      Serial.print("Received: ");
      Serial.println(command);

      if (command == "ON") {
        digitalWrite(LED_PIN, HIGH);
        Serial.println("LED ON");
      } else if (command == "OFF") {
        digitalWrite(LED_PIN, LOW);
        Serial.println("LED OFF");
      }
    }
  }
}

Important code sections

  • WiFi.begin() connects the ESP32 to an internet-enabled Wi-Fi network.
  • The MQTT client uses the Adafruit IO host, port, username, and AIO Key to authenticate.
  • mqtt.subscribe(&bulbControl) subscribes to the Kixorr_28/feeds/bulb-control feed.
  • connectMQTT() checks the broker connection and retries if it is disconnected.
  • mqtt.readSubscription() reads values delivered through the feed.
  • The command is compared with ON/OFF, then GPIO 2 is set HIGH/LOW.

11 / WHAT I LEARNED

Learning reflection

This task helped me understand how cloud-based IoT automation connects an event to a physical device. I learned how IFTTT uses a trigger/action Applet, how Adafruit IO provides a feed for the command, and how MQTT delivers the update to an ESP32. The workflow extends the previous dashboard-control task: instead of a user manually selecting a command, an external event can initiate the process.

The project also reinforced the importance of internet connectivity, accurate feed configuration, correct MQTT subscriptions, protected credentials, and step-by-step testing across multiple services.

Final result: An external event triggers IFTTT, which updates the Adafruit IO feed. The ESP32 receives the value over MQTT and changes GPIO 2 so the LED responds.
